`GET /api/metrics` и UI показывают подтверждённые случаи по типу, линии и посту, распределение установленной/неизвестной причины, интервалы по изделию, посту, оператору и смене, а также подтверждённые ошибки по ключу сопоставимых работ. Линия и смена доступны только при передаче этих полей в событии v2. Причину и ошибку оператора задаёт контролёр в решении; система не устанавливает вину по одному сигналу. В стартовом синтетическом наборе подтверждённых ошибок оператора нет.

## Воспроизведение

1. `python -m unittest discover -s tests -v` — ядро, сквозной маршрут, HTTP-роли и эмулятор.
2. `python -m qc.demo` — UI с эталоном 5 проверенных, 3 с последним решением `confirmed`, 1 без пригодного контроля; I-005 показывает повторную обработку, I-006 — поздний входной факт и пересмотр прежнего решения.
3. `node tests/browser_smoke.js` при доступных Playwright/Chrome и токенах — обзор линии, I-003–I-006, действие контролёра, перерасчёт, ACK и мобильная ширина.

Доказательство ограничено локальными синтетическими событиями и перечисленными проверками. Максимальное соответствие критериям **не подтверждено**.
