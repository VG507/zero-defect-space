## Принятые решения

| Решение | Причина |
|---|---|
| План будет храниться в репозитории | Он станет рабочим документом для реализации и проверки. |
| MVP — модульный сервер с единым событийным журналом и двусторонним эмулятором | Покрывает обязательный сквозной сценарий без непроверенных реальных интеграций. |
| Дополнительные баллы выполняются после ворот базовой готовности | Демонстрация основного продукта не зависит от расширений. |
| Начало реализации не зависит от данных заказчика | По ТЗ допустимы синтетические события и работающий эмулятор; реальные параметры отмечаются проектными предположениями. |
| Первый исполняемый контур — Python stdlib + SQLite | В локальной среде нет FastAPI/SQLAlchemy и Docker daemon; это временное отклонение ради проверяемого запуска. Контракты и границы модулей готовятся к смене транспорта/хранилища. |

## Ошибки

При проверке среды обнаружено отсутствие FastAPI, SQLAlchemy и активного Docker daemon. Выбран исполняемый контур без этих зависимостей; соответствие целевому стеку пока не достигнуто.
Браузерный helper не запустил сервер через PowerShell-специфичную команду; сервер запущен напрямую. Playwright не нашёл собственный Chromium; для smoke-теста выбран установленный локальный Chrome через executablePath.
При изменении расчёта входного брака допущена синтаксическая ошибка скобок; обнаружена полным прогоном тестов и исправлена. Повторный прогон обязателен до отметки этапа.
При расширении контекста случая повторный прогон выявил нестабильную проверку late event после решения. Убрано избыточное сравнение с повторным `utc_now()`; проверка опирается на факт уже существующего решения и время события.
В текущем проходе `rg qc/*.py` не сработал в Windows из-за шаблона пути; повторить поиск как `rg ... qc -g '*.py'`.
При первом browser smoke использовался занятый порт 8765 от прежнего процесса; чистый запуск на 8877 и `QC_BASE_URL` прошёл. После добавления обзора возникла неоднозначность выбора кнопки I-003; тест уточнён до реестра. Полный тестовый прогон выявил нестабильный порядок двух решений с одинаковым временем; порядок изменён на последовательность записи.
